# whim 파일럿 테스트 가이드

인스타에서 저장한 장소를 지도 위에 올려놓고, 내 저장이 몰려 있는 동네를
알려주는 앱입니다. 파일럿에서 확인하려는 것은 딱 두 가지입니다.

1. **담기가 3초 안에 끝나는가**
2. **담아둔 곳에 실제로 가는가**

기능 제안보다 "이 상황에서 이게 안 됐다"가 훨씬 도움이 됩니다.

---

## 1. 설치 (테스터)

1. 초대 메일의 링크를 **테스트에 참여할 구글 계정으로** 엽니다.
2. `테스터 되기` → `Google Play에서 다운로드` 순서로 누릅니다.
3. Play에서 whim을 설치합니다. 앱 이름은 **whim**, 아이콘은 **파란 배경의 흰
   지도 핀**입니다.

> 초대 메일을 받은 계정과 폰에 로그인된 계정이 다르면 "이 앱은 사용할 수
> 없습니다"가 뜹니다. 계정을 확인해 주세요.

## 2. 첫 사용 — 공유 시트에서 whim 찾기

whim에는 검색 화면이 없습니다. **다른 앱에서 공유를 누르는 것이 유일한 입구**
입니다.

1. 인스타그램에서 가보고 싶은 게시물을 엽니다.
2. 종이비행기 아이콘 → **공유 대상 더 보기**(또는 `...` → 링크 복사 옆의
   공유) 를 누릅니다.
3. 앱 목록에서 **whim**(파란 지도 핀)을 찾아 누릅니다.
   - 안 보이면 목록을 **왼쪽으로 넘기거나 아래로 스크롤**하세요. 처음에는
     뒤쪽에 있다가 몇 번 쓰면 앞으로 나옵니다.
   - 길게 눌러 **고정(핀)** 해두면 매번 찾지 않아도 됩니다.
4. whim이 뜨면서 바텀시트가 열립니다. **상호명을 입력**하고 후보 중 하나를
   누르면 저장됩니다.

### 인스타는 가게 이름을 같이 보내주지 않습니다

인스타 공유에는 링크만 담겨 있어 검색창이 비어 있습니다. 그래서 시트가 열리면
**키보드가 바로 올라옵니다** — 가게 이름을 그대로 치시면 됩니다.
네이버지도·카카오맵에서 공유하면 이름이 자동으로 채워집니다.

## 3. 봐주셨으면 하는 것

- 공유 → 저장까지 **몇 초** 걸리는지 (체감)
- 후보 목록에 **원하는 곳이 있는지**
- 지도에서 **동네가 제대로 묶이는지** (파란 원 + `○○동 N곳`)
- 주말에 그 동네에 갔을 때 **`지금 가기`가 쓸 만한지**

## 4. ⚠️ 데이터가 사라지는 경우 (중요)

이 앱은 **로그인이 없습니다.** 기기에 붙은 익명 계정으로 저장합니다. 그래서
아래 경우 **담아둔 곳이 전부 사라지고 복구할 방법이 없습니다.**

- 앱을 삭제했다가 다시 설치
- 설정 → 애플리케이션 → whim → **저장공간 → 데이터 삭제**
- 기기 초기화 / 다른 기기로 교체

테스트 기간에는 **앱을 지우지 말아 주세요.** 중단하고 싶으시면 지우기 전에
알려주시면 됩니다. (계정 로그인은 파일럿 이후에 붙일 예정입니다.)

그 외에는 안전합니다. 비행기모드·지하철처럼 네트워크가 없는 곳에서 담아도
저장되고, 연결되면 알아서 올라갑니다.

## 5. 버그 제보

- 무엇을 하다가 (예: 인스타 릴스 공유 → 시트에서 검색)
- 무엇을 기대했고 뭐가 나왔는지
- 가능하면 **스크린샷과 시각**

크래시는 자동으로 수집되지만, 어떤 상황이었는지는 알려주셔야 원인을 찾습니다.

# 운영자용 (배포하는 사람)

## 내부 테스트 트랙 등록

1. Play Console → 앱 만들기 (앱 이름 `whim`, 언어 한국어, 앱/무료).
2. **테스트 → 내부 테스트 → 새 버전 만들기**에 `app-release.aab` 업로드.
   ```bash
   flutter build appbundle --dart-define=KAKAO_REST_API_KEY=<REST 키> --dart-define=KAKAO_NATIVE_APP_KEY=<네이티브 앱 키>
   ```
   산출물: `build/app/outputs/bundle/release/app-release.aab`
3. **테스터 목록**에 파일럿 참가자 이메일을 넣고 링크를 복사해 보냅니다.
4. 정식 심사는 필요 없지만, 앱 콘텐츠(개인정보처리방침·광고·데이터 안전)를
   채워야 저장이 됩니다. 데이터 안전에는 **위치(지금 가기)** 와
   **앱 활동(저장한 장소)** 을 수집한다고 적습니다.

### 업로드 전 반드시: 카카오 키 해시 등록

릴리스 빌드는 디버그와 서명 키가 달라, 키 해시를 등록하지 않으면
**테스터 폰에서 지도가 빈 화면으로 뜹니다.**

- 릴리스 키 해시: `bI3rHdr6b4JtC08ujjsf3eJkofc=`
- Play App Signing을 쓰면 구글이 다시 서명하므로, 업로드 후
  **Play Console → 앱 무결성 → 앱 서명 키 인증서의 SHA-1**로 만든 해시도
  카카오 디벨로퍼스 → 플랫폼 → Android에 **추가로** 등록해야 합니다.

```bash
keytool -exportcert -alias whim -keystore C:\dev\whim-release.jks | openssl sha1 -binary | openssl base64
```

## versionCode 규칙

Play는 같은 versionCode를 두 번 받지 않습니다. `pubspec.yaml`의
`version: 1.0.0+1`에서 **`+` 뒤가 versionCode**입니다.

- 업로드할 때마다 **`+` 뒤를 1 올립니다** (`1.0.0+2`, `1.0.0+3` …).
- 사용자에게 보이는 이름(`1.0.0`)은 기능이 바뀔 때만 올립니다.
- 되돌릴 수 없습니다. 한 번 올린 versionCode보다 작은 값은 업로드가 거부됩니다.

## 파일럿 지표 보는 곳

Firestore 콘솔 → **`stats` 컬렉션**. 참가자마다 문서 하나이고, 앱을 쓸 때마다
갱신됩니다.

| 필드 | 뜻 | 기준 |
|---|---|---|
| `captureRate` | 담기 완료율(%) | **70 미만이면 공유 플로우부터 고친다** |
| `visitRate` | 저장→방문 전환율(%) | 목표 30 |
| `pinCreated` / `pinAbandoned` | 담기 성공·포기 횟수 | |
| `pins` / `visitedPins` | 담은 곳·다녀온 곳 | |

`null`은 아직 분모가 0이라는 뜻입니다(0%와 구분).

원본 이벤트는 `users/{uid}/events`에 있고, Firebase Analytics에도 같은
이벤트가 올라갑니다. 크래시는 **Crashlytics**에서 봅니다.
